# Game Dev OS – Minimum Viable Product (MVP)

## Purpose

The MVP exists to solve one clear problem:

Help indie game teams organise and learn from their playtests without relying on multiple disconnected tools.

The goal is not to build the entire Game Dev OS.

The goal is to build one workflow that is genuinely useful and forms the foundation for future modules.

---

# Target Users

Primary users:

- Solo indie developers
- Student game development teams
- Small indie studios (2–10 people)

These users regularly:

- Run playtests
- Collect feedback
- Track bugs
- Plan improvements
- Build weekly prototypes

---

# MVP Goal

After every playtest, a team should be able to answer:

- What worked?
- What didn't work?
- Which issues are most important?
- Who is fixing them?
- What should we improve before the next build?

---

# MVP Features

## 1. Authentication

Users can:

- Create an account
- Sign in
- Sign out

(Authentication will be added after the UI foundation.)

---

## 2. Projects

Users can:

- Create a project
- View project dashboard
- Edit project information

Each project becomes the central workspace.

---

## 3. Playtests

Users can create:

- Playtest sessions
- Build version
- Date
- Objective
- Tester list
- Notes

---

## 4. Feedback

Each feedback entry includes:

- Category
- Severity
- Description
- Suggested improvement

Categories include:

- Fun
- Clarity
- Balance
- Bugs
- Materials
- Map Control
- Controls
- Performance

---

## 5. Tasks

Feedback can become tasks.

Each task has:

- Title
- Description
- Priority
- Status
- Assigned developer

Statuses:

- Todo
- In Progress
- Done

---

## 6. Dashboard

Dashboard displays:

- Current project
- Latest playtest
- Open tasks
- High priority issues
- Recent activity

---

# NOT Included

The MVP intentionally excludes:

❌ AI Assistant

❌ Publisher Database

❌ Budget Planner

❌ Team Chat

❌ Steam Integration

❌ Community Features

❌ Portfolio Pages

❌ Marketplace

These features are part of the long-term vision but are not necessary to validate the product.

---

# Success Criteria

The MVP is successful if a development team can:

1. Create a project
2. Record a playtest
3. Log feedback
4. Convert feedback into tasks
5. Track progress between playtests

without needing external tools.

---

# MVP Philosophy

Build one workflow exceptionally well before expanding.

Every future feature must naturally connect to the existing workflow.

The MVP is the foundation of Game Dev OS—not the finished product.
