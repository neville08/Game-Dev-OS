# Game Dev OS – Product Vision

## Mission

Game Dev OS exists to simplify the way indie game developers build games.

Instead of juggling multiple disconnected tools for documentation, planning, playtesting, bug tracking, budgeting, milestones, and communication, Game Dev OS provides one connected workspace designed specifically for game development.

Our goal is to reduce friction so developers can spend more time creating games and less time managing information.

---

# Vision

To become the operating system for indie game development.

Game Dev OS is not another generic project management tool.

It is a workspace built around how games are actually made.

Every feature should feel like it belongs to the game development process.

---

# Problem

Today, indie teams often use:

- Google Docs for GDDs
- Notion for notes
- Trello or Jira for tasks
- Google Sheets for budgets
- Discord for communication
- Google Forms for playtests
- Random folders for screenshots and builds

Information becomes fragmented.

Developers waste time searching instead of building.

---

# Solution

Game Dev OS connects every stage of development into one workspace.

Projects become the center of everything.

Inside each project developers can manage:

- Design documentation
- Playtests
- Bugs
- Tasks
- Milestones
- Builds
- Budget
- Team members
- AI assistance
- Publisher research (future)

Everything stays connected.

---

# Product Principles

## 1. Built for Game Developers

Every feature must solve a real problem experienced during game development.

If a feature doesn't improve game development, it doesn't belong.

---

## 2. Reduce Friction

Every click matters.

Every workflow should remove unnecessary work.

The software should help developers think less about organisation and more about making games.

---

## 3. Everything is Connected

Projects are the heart of the platform.

Playtests create tasks.

Tasks relate to milestones.

Bugs relate to builds.

Design documents relate to systems.

Nothing exists in isolation.

---

## 4. AI Assists, Never Replaces

Artificial Intelligence should speed up developers.

It should never remove creative control.

AI should suggest.

Developers decide.

---

## 5. Build Modularly

Each module should provide value on its own.

Examples:

- Playtests
- Tasks
- Design Docs
- Budget
- Builds

Together they become the complete operating system.

---

## 6. Professional Quality

Game Dev OS should be designed as production software.

Readable code.

Scalable architecture.

Consistent design.

Clear documentation.

Version control.

---

# Long-Term Goal

Become the default workspace that indie developers open every morning before they begin building their game.

Instead of asking:

"Which app is my information in?"

Developers simply open Game Dev OS.
